# Architecture

This is a Home Assistant add-on repository (the layout HA's Add-on Store expects: `repository.yaml` at the root plus one directory per add-on, each with its own `config.yaml`).

- `repository.yaml` — repo-level metadata shown in the HA Add-on Store.
- `addon/` — the "Elias ems" app: a React Router 8 (React, TypeScript) app that becomes its UI.
  - `addon/config.yaml` — HA add-on manifest (slug, arch, ingress). The app is reached through HA's ingress on port 3000, not exposed directly.
  - `addon/Dockerfile` — multi-stage build on `node:22-alpine`: `npm run build` runs in a build stage, then `server.js`, `build/server`, `build/client`, and prod deps are copied into the runtime image, which runs `npm run start` (a small custom Express server, not `react-router-serve` — see [CLAUDE.md](../CLAUDE.md) for why: Home Assistant's ingress proxy needs a per-request `basename` that `react-router-serve` can't provide).
  - `addon/app/` — app source, with routes under `addon/app/routes/` (Remix-style file naming, wired up by `flatRoutes()` in `addon/app/routes.ts`).
  - `addon/react-router.config.ts`, `addon/vite.config.ts`, `addon/tsconfig.json` — framework, bundler, and TypeScript config.
  - `.react-router/` (gitignored) — per-route types generated by `react-router typegen`, imported as `./+types/<route>`.

The EMS logic itself (battery control, PV curtailment, price integration — see [roadmap.md](roadmap.md)) isn't implemented yet; the app currently only scaffolds a "Hello World" page plus a settings page for picking PV entities.
